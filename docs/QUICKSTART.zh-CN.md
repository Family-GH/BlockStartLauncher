# 快速上手（零基础版）

适用版本：BlockStart Launcher V0.5.3b，Windows 系统。

这份文档按“第一次打开启动器”的顺序写成，每一步都对应界面上的实际按钮。照着走完，一般十几分钟就能进游戏；后面几节列出最容易出错的地方，动手前建议扫一眼。

## 一、下载与放置

1. 打开 Releases 页面，下载 `BlockStartLauncherPortable.zip`（推荐）。
2. 解压到一个**纯英文、无空格**的路径，例如 `D:\Games\BSL`。
   - 不要放在 `C:\Program Files`、桌面、下载文件夹里，也不要直接双击压缩包“在线打开”。
3. 解压后目录里能看到 `BlockStartLauncherPortable.exe` 和 `_internal` 文件夹，两者要放在一起，不能只拷 exe。

如果下载的是单文件版 `BlockStartLauncher.exe`，可以放在任意目录直接运行，首次启动会自行解包到 `%LOCALAPPDATA%\BlockStartLauncher`。

## 二、第一次启动

双击 `BlockStartLauncherPortable.exe`。

- 系统提示“Windows 已保护你的电脑”：点「更多信息 → 仍要运行」。程序没有商业签名证书，这个提示不代表文件有问题。
- 安全软件提示拦截：选择「允许本次操作」，或把该目录加入信任。单文件版在网络受限或杀软较严的环境下更容易被拦，这种情况直接用便携版。
- 启动器会申请管理员权限，因为要往游戏目录写文件。点「是」，点「否」会退出。

启动后先不要急着点“启动游戏”，按下面的顺序配置一次，之后每次都能直接用。

## 三、账户

1. 左侧切到「账户」，点「微软正版登录（推荐）」。
2. 启动器会自动申请设备代码并复制到剪贴板，同时尝试打开登录页。
3. 浏览器没弹出时，在登录窗口点蓝色链接，或点「复制登录链接」，手动打开 `https://www.microsoft.com/link` 粘贴代码。
4. 按网页提示登录，成功后账户会自动出现在列表里。
5. 没有正版账户时可用「离线账户（免登录）」，只能单机/离线游玩，不能用官方皮肤与披风。

注意：登录过程中不要连续点按钮，也不要关掉登录窗口，关窗口会取消本次登录。

## 四、Java 环境

启动器会自动查找本机 Java。想确认或手动指定：

1. 切到「设置」→「Java 运行环境」。
2. 列表里有检测到的版本就直接选；没有就点「手动选择」，选中 `bin\java.exe`。
3. 实在没有 Java，可以让启动器下载对应运行时，也可以在启动游戏时按提示处理。

常见位置：`C:\Program Files\Java\jdk-17\bin\java.exe`、`C:\Program Files\Eclipse Adoptium\...\bin\java.exe`，PCL 自带的通常在 `.minecraft\runtime` 或 `PCL\runtime`。

## 五、新建实例并启动

1. 回到「主页」，点「新建实例」。
2. 在列表里选游戏版本（正式版/快照按需选），确认实例名，点「创建」。
3. 需要模组的话，在同一窗口选加载器：Fabric、Forge、NeoForge、Quilt，留空就是原版。
4. 回到主页点「启动游戏」。第一次会自动下载游戏文件，进度可看，随时能停。
5. 想改内存、窗口大小、全屏、额外参数或自动进服地址，进「游戏实例」→「实例设置」单独配置；不填就跟随「设置」里的全局值。

一个实例就是一套独立环境：模组、存档、配置、资源包互不干扰。想同时玩原版和大型整合包，建两个实例即可。

## 六、装模组

1. 切到「模组」，确认顶部显示的是目标实例。
2. 输入关键词（建议用英文名，如 `JEI`、`Create`、`Sodium`），点「搜索」。
3. 点结果查看介绍、分类、支持的游戏版本与加载器，在「选择版本」里挑与你的游戏版本、加载器都匹配的那一版，点「下载到当前实例」。
4. 下载完在「已安装的模组」里能看到，勾选为启用，取消为禁用（改扩展名，不删文件）。
5. 启动前如果提示“混用加载器”或“重复 modid”，按提示处理，否则容易进不去游戏。

## 七、导入整合包

1. 切到「整合包」，把整合包文件拖进窗口，或点「选择整合包文件」。
2. 支持 `.mrpack`、CurseForge 压缩包、MultiMC 实例和标准 `.minecraft` 目录结构。
3. 启动器会识别游戏版本与加载器并新建实例，缺的模组从 Modrinth 补；「缺失文件」里列出的项目要处理完再启动。

## 八、资源包与光影

「资源」页搜索后下载到当前实例即可。光影需要先在游戏内装好对应的光影加载器（如 Iris / OptiFine），再在游戏里启用。

## 九、存档与备份

- 「实例」页点「备份存档」，备份写到数据目录的 `backups` 下，不改动原存档。
- 「存档管理」可导入、删除、查看已有备份。
- 备份过程中取消不会留下坏文件，程序会自行清理。

## 十、出问题时怎么查

1. 「修复工具」→「检查文件」，列出缺失或校验不符的文件，可修选中项或全修；本地库异常可用「只修复运行库」。
2. 游戏崩溃 → 「设置」→「诊断与帮助」→「查看崩溃原因」，会读最新崩溃报告与日志末尾，常见原因（Java 版本不对、模组冲突、内存不足）会直接指出。
3. 版本列表拉不出来 → 「重试版本列表」，或到「设置」→「下载」切换下载线路。
4. 启动器自身异常 → 「修复工具」→「诊断启动器」→「执行修复」。

## 十一、这些操作容易出事，别做

- 不要删除运行中的 `.bsl_runtime` 目录。
- 不要把 `accounts.json` 发给任何人，也不要把别人的账户文件拷进来；凭证按 Windows 用户加密，换机器解不开。
- 不要手工改 `settings.json`，改坏了虽然会回滚 `.bak`，但没必要冒险。
- 不要同时开两个启动器实例跑同一份游戏目录。
- 不要在没有备份的情况下直接删实例目录；要删请用「删除实例」。
- 不要用第三方“加速器”去替换启动器下载的文件，容易造成校验失败。

## 十二、迁移与卸载

- 迁移：复制整个数据目录 `%LOCALAPPDATA%\BlockStartLauncher` 和启动器本体，到新机器后账户需重新登录。
- 卸载：删除启动器目录和数据目录即可，程序不写注册表、不装系统服务。

## 十三、版本与更新

「设置」→「启动器更新」默认查 GitHub Releases，可点「检查更新」；也可以在「其他更新源」里填多个 JSON 清单地址，启动器会合并所有来源取最高版本，某个地址失败自动换下一个。
